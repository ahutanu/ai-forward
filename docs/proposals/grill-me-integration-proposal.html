Core design constraint
Ask the human only for decisions. Facts are researched by the agent; visual unknowns are prototyped; settled decisions are not re-asked.
Proposal · 27 Sep 2026

Recommended direction

Make decision quality intrinsic, without turning every run into an interview.

Adopt the design-tree and frontier mechanics from grilling, but integrate them as a bounded Decision Interrogation Protocol inside AI-Forward's existing Rigor stages and gates.

Two surfaces, one shared protocol

Early interrogation where ambiguity is cheapest to resolve; a closure gate after the artifact is drafted when unresolved human decisions remain.

Recommended
01 · EARLY

Intrinsic frontier in /specify and /ui-design

After grounding, ask only the currently answerable product or direction decisions that materially shape the artifact. Recompute after each answer.

02 · LATE

Decision Closure Gate after four workflows

After /specify, /ui-design, /define-architecture, and slice-level /design, expose unresolved decisions before handoff.

03 · EFFICIENT

Summary first, then one-by-one

Show the entire current frontier in a compact table, then walk questions sequentially with recommendations, fast-accept, defer, and prototype routes.

What to preserve from grilling

The strongest idea is not “ask more questions.” It is to model dependencies between decisions and ask each question only when its prerequisites are settled.

Important adaptation: unlike standalone /grill-me, AI-Forward should not be “relentless” by default. The protocol is bounded by the current artifact, asks only consequential unresolved decisions, and stops when further questioning would not change the artifact or its next handoff.

Proposed name

Decision Interrogation Protocol is clearer inside the pack than “grilling”: it describes the purpose, fits the Rigor vocabulary, and can be referenced consistently from several skills without introducing another user-facing command.

Shared interaction model

A frontier summary followed by a focused decision walk.

The interaction is optimized for both scanability and focus: the user sees the whole decision surface first, but answers one question at a time.

1. GroundRead specs, code, evidence, and prior decisions.
2. ClassifyFact, human decision, prototype-needed, or safe deferral.
3. SummarizeShow the current frontier in the three-column table.
4. WalkAsk one-by-one; recommendation visible; recompute dependencies.
5. CommitConfirm shared understanding, update artifact, record decision.

The decision classifier

Agent resolves

Fact

Can be established from the repo, an authoritative source, a spike, a measurement, or a tool. It never becomes a user question.

Human answers

Decision

Product intent, experience direction, trade-off, risk acceptance, priority, or an irreversible choice with multiple legitimate answers.

Make evidence

Ungrillable

Cannot be settled by discussion: how an interaction feels, whether a layout works, or whether an unfamiliar contract behaves as expected. Prototype or spike it.

Question eligibility

Ask now when…Do not ask when…
The answer materially changes scope, acceptance criteria, archetype, architecture, contracts, phasing, or risk acceptance.The answer is discoverable from the repository, documentation, code, or an executable probe.
All prerequisites are settled, so the question is on the current frontier.A prerequisite decision is still open; hold it for a later frontier.
There are multiple defensible choices and the human owns the trade-off.There is a repository-standard answer or an authoritative constraint already fixes it.
Deferral would create expensive downstream rework.Deferral is safe and the consequence is explicit; record it as a flagged risk instead.

Efficiency controls

1
Default to one-by-one after the table.

This matches the requested interaction and avoids the cognitive load of drafting a multi-answer response, while preserving the frontier's scanability.

2
Offer “Accept all recommendations in this frontier.”

A fast path for low-controversy rounds; the user can still override individual items before confirmation.

3
Support “I don't know” as a first-class answer.

The protocol responds by researching, prototyping, recording a bounded assumption, or deferring with consequence — never by inventing certainty.

4
Use a significance threshold.

Do not interrupt for choices that can be reversed cheaply and do not alter the current artifact or next handoff.

5
Stop on decision closure, not question count.

The frontier is empty when remaining unknowns are factual work, prototype work, or explicitly accepted residual risk.

Skill integration

One protocol, surfaced differently by workflow.

The protocol should be a shared knowledge standard referenced by skills, not copied as four divergent interview implementations.

/specify

Intrinsic + closure
After Stage 1

Build the first frontier from problem framing: user, core job, scope boundary, success measure, governance choices.

Before evidence

Ask only decisions that determine what research or comparables are relevant. Research facts in parallel.

Closure gate

Resolve open product, UX, UI, NFR, or commercial-model decisions before the spec becomes Accepted or hands off.

/ui-design

Intrinsic + closure
After grounding

Build a direction frontier: JTBD, emotional state, archetype, density, references, anti-goals, brand constraints.

Prototype route

If the answer is visual or experiential, build 2–3 minimal variants instead of continuing to ask abstract preference questions.

Closure gate

Resolve remaining direction, trade-off, and state-priority decisions before the design language and mockup are approved.

/define-architecture

Closure only
During workflow

Continue using Rigor interrogation and spikes; do not add conversational ceremony where evidence can settle the question.

Closure gate

Surface unresolved boundary, consistency, identity, build-vs-buy, durable-data, rollout, or risk-acceptance decisions after the draft/council review.

Record

Answers that bear load become ADRs; lower-weight choices become decision notes.

/design per slice

Closure only
Scope note

No separate design-slice skill exists today; treat this as /design scoped to one architecture delivery slice.

Closure gate

Surface unresolved contract, failure disposition, migration, UX state, test-oracle, or accepted-risk decisions before implementation handoff.

Record

Update the design's flagged-risk section and decision notes; block handoff only for required-now questions.

Proposed pack changes

Minimal source changes, centralized behavior.

Add one shared knowledge document and targeted references in four skills. Avoid a new command unless later usage shows value beyond these workflows.

1. New shared standard

pack/knowledge/decision-interrogation.md

DI1 — Model unresolved decisions as a dependency tree.
DI2 — The current frontier contains only questions whose prerequisites are settled.
DI3 — Resolve facts autonomously; ask the human only for decisions.
DI4 — Show the frontier first as:
      Question | What it is needed for | Recommendation
DI5 — Walk the frontier one question at a time; recompute after every answer.
DI6 — "I don't know" routes to research, spike, prototype, bounded assumption, or safe deferral.
DI7 — Ungrillable visual/experiential questions require a prototype, not more prose.
DI8 — Do not hand off while a required-now human decision remains open.
DI9 — End with a shared-understanding confirmation before updating/acting.
DI10 — Persist answers in the artifact, decision notes, or ADRs at the correct weight.

2. /specify insertion

After Stage 1 — OPEN:

If the frame contains consequential human-owned decisions, run the Decision
Interrogation Protocol before Stage 3. Build the current frontier from the problem,
primary user, core scenario, scope boundary, success measures, governance choices,
and UX/UI direction. Resolve discoverable facts yourself. Show the frontier table,
then walk it one question at a time. Recompute the frontier after every answer.
Do not ask decisions that evidence or a prototype must settle.

At Stage 5 — CONVERGE:

Run the Decision Closure Gate. If required-now product, UX, UI, NFR, commercial,
or risk-acceptance decisions remain open, do not mark the spec Accepted or hand off.
Summarize the open frontier, walk it sequentially, update the spec, then ask the
user to confirm shared understanding.

3. /ui-design insertion

After Stage 1 — OPEN:

If direction is underdetermined, run the Decision Interrogation Protocol over the
JTBD, emotional state, archetype, density, references, anti-goals, and constraints.
For visual or experiential questions that cannot be settled honestly in prose,
stop questioning and build the smallest useful comparison prototype. Return with
the evidence and place the now-answerable decision on the next frontier.

At Stage 5 — CONVERGE:

Run the Decision Closure Gate before approving the design language or mockup.
Required-now direction and trade-off decisions block approval. Mechanical facts
(contrast, token use, current implementation shape) are resolved by the agent;
accessibility vetoes are resolved by evidence, not user preference.

4. Shared closure block for architecture and slice design

Decision Closure Gate (before the final status table):

Inspect the confidence ledger, flagged risks, unresolved veto conditions, and the
artifact's open-question section. Classify each item as Fact, Human decision,
Prototype/Spike needed, Deferred-safe, or Accepted residual risk.

If Human decisions are required now:
1. Show the current frontier as Question | What it is needed for | Recommendation.
2. Walk the questions one by one, preserving disagreement and "I don't know".
3. Recompute the frontier after each answer.
4. Update the artifact and the appropriate ADR/decision note.
5. Ask the user to confirm shared understanding before handoff.

If none are required now, proceed without conversational ceremony.

5. Artifact addition

Add to spec / architecture / design templates:

## Open decisions
| Question | Needed for | Recommendation | Classification | Status / decision record |
|---|---|---|---|---|

This section is empty when the Decision Closure Gate passes. Deferred items name
their consequence and validation trigger; ADR-weight decisions link the ADR.

Recommended implementation order

1
Introduce the shared standard and template section.

This establishes one contract before any skill references it.

2
Add intrinsic interrogation to /specify and /ui-design.

These are the workflows where human intent and direction are cheapest to clarify early.

3
Add the closure gate to all four workflows.

Use identical wording so behavior does not drift.

4
Add eval cases.

Prove facts are researched, decisions are asked, dependent questions wait, ungrillable questions route to prototype/spike, and no-question runs stay uninterrupted.
